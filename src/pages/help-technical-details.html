Hosting

A Cloudflare Worker, not just static hosting

The live site is a Cloudflare Worker. Its configuration (wrangler.jsonc) points Cloudflare's asset handler at public/, the folder the build script generates — so almost every request is served as a plain static file, exactly like conventional web hosting. The one addition is a small JSON API endpoint, /api/subscribe, that the newsletter signup form talks to — see Newsletter below.

Deployment is automatic: Cloudflare's GitHub integration watches the main branch, and every push triggers a fresh build and deploy — no separate deploy step to run by hand, and typically live in well under a minute. This is the mechanism behind step 5 in Making a change ("the live site rebuilds itself").

DNS

Also managed in Cloudflare

The kingtonparishes.org.uk domain's DNS lives in the same Cloudflare account as the Worker, with the domain attached to the Worker as a custom domain. That's a deliberate, common pairing — Cloudflare can issue and renew the site's TLS certificate and route traffic straight to the Worker without a separate DNS provider in the loop. It replaced the previous host (Wix) at go-live on 6 September 2026; see /updates for that migration's own build-log entries.

Newsletter

InSpire Newsletter signups, via MailerLite

The InSpire Newsletter signup form doesn't talk to MailerLite directly from the browser. Instead:

1. The form posts to the Worker

A visitor's email (and optional name) is sent to this site's own /api/subscribe endpoint — never straight to a third party.

2. The Worker calls MailerLite

Server-side code (src/worker/subscribe.mjs) validates the address, then calls MailerLite's API to add it to the "InSpire Newsletter" group.

3. Immediate subscription

Double opt-in is currently switched off in MailerLite (the sending domain isn't yet verified for it), so a successful signup is immediate — no confirmation email is sent. See CLAUDE.md for where this reverts if that changes.

API security

How the API endpoint is secured

The MailerLite key is a Cloudflare secret

It's never committed to GitHub and never appears in this repository — only the non-secret group id lives in wrangler.jsonc. On a failure, only MailerLite's own error status is logged server-side; the key and the raw request are never written to a log.

Server-side validation

Email format and length, and name length, are checked before anything reaches MailerLite — the API is never handed unvalidated input.

A honeypot field

A hidden form field real visitors never see, but generic bots filling in every field will. A filled honeypot is answered with a normal success response rather than an error, so bots don't learn to detect and route around it.

Security response headers

Every response carries a Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, a restrictive Permissions-Policy, and HSTS (public/_headers) — defence in depth against injected scripts, clickjacking and downgraded connections, on every page, not just the API.

Dependency scanning on every push

A git hook runs npm audit --audit-level=high before any push can complete, blocking it outright if a dependency carries a known high or critical severity vulnerability.

A published disclosure contact

An RFC 9116 security.txt points anyone who finds a real vulnerability at a monitored contact address, rather than leaving them no way to report one responsibly.

The code

Where it all lives

Every piece of this — page content, templates, the build script, the styling, and the Worker code behind the newsletter API — lives in one public GitHub repository: github.com/magicobject/kington-parishes. Every commit that reaches main is tagged with its own build number (e.g. build-2026.09.08.005), so any past version of the site can be checked out by name — see /updates for the human-readable version of that same history.
