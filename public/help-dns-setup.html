    DNS setup, in detail

    A closer look at kingtonparishes.org.uk's actual DNS records — what each one is for, and why the website and the parish's email addresses are handled by two completely different companies. DNS records are public information, so everything below is just a plain lookup anyone can run, not anything confidential.

    The web address Email — 123 Reg / GoDaddy The other records
    The web address

    A records point at Cloudflare, not a server

    Both kingtonparishes.org.uk and www.kingtonparishes.org.uk resolve to two Cloudflare addresses (currently 104.21.13.200 and 172.67.157.83) — not the Worker's own address, because there isn't one to point at directly. These are shared Cloudflare "proxy" addresses: every visitor's request lands at Cloudflare first (this is also what provides the TLS certificate and the security headers described in Technical details), which then hands it internally to the Worker. The domain's nameservers — mustafa.ns.cloudflare.com and suzanne.ns.cloudflare.com — are what makes Cloudflare the authority for every record described on this page, not just the website's own.

    Email — 123 Reg / GoDaddy

    The website and the email are on separate providers

    Even though Cloudflare controls the domain's DNS, none of the parish's email actually flows through Cloudflare. Two MX records (the record type that says where a domain's email should be delivered) point everything at GoDaddy's mail infrastructure instead:

    smtp.secureserver.net (priority 0)

    The primary mail handler — lower priority numbers are tried first, so this is where incoming mail for the domain is delivered under normal conditions.

    mailstore1.secureserver.net (priority 10)

    A secondary/backup mail store, tried only if the first is unavailable.

    secureserver.net is GoDaddy's own shared infrastructure — and 123 Reg is a GoDaddy-owned UK brand, so this is exactly what the parish's registrar handling both domain redirection and mailbox hosting looks like from the DNS side: the parish's real mailboxes live on 123 Reg/GoDaddy's servers, entirely separate from the Cloudflare Worker that serves this website.

    The other records

    What the non-A record lines are for

    A domain's DNS carries more than just "where's the website" and "where's the email" — several TXT records (plain-text entries that don't route any traffic themselves, just publish information) do other jobs:

    SPF (Sender Policy Framework)

    Lists which mail servers are allowed to send email claiming to be from kingtonparishes.org.uk — currently GoDaddy's servers (for real parish email) and MailerLite's sending infrastructure (for the InSpire Newsletter, see Newsletter). Other mail providers check this record to help tell genuine mail from spoofed mail.

    DMARC

    Sits alongside SPF and says what should happen to mail that fails those checks. It's currently set to p=none — monitor only, nothing gets rejected because of it yet — with a summary report emailed to a Cloudflare-provided reporting address rather than anyone at the parish having to watch it directly.

    Google site verification

    Proves to Google Search Console that whoever added this record controls the domain — unrelated to email, and safe to ignore day to day.

    MailerLite domain verification

    The same idea, for MailerLite: proves domain ownership as part of setting up the newsletter's sending domain.

    One unexplained record

    A short plain-text value with no obvious purpose from the DNS alone — most likely a leftover verification code from a past service. Worth checking with whoever manages the Cloudflare account before ever removing it, in case it's still quietly relied on by something.

    DNS records can change, so treat the specifics above as a snapshot taken 8 September 2026, not a permanent fact — a public DNS lookup (the same kind used to write this page) takes Claude moments to re-run if this page might be out of date.
