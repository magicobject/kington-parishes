    Making a change

    Once you're set up, here's what actually happens each time you'd like something on the website updated.

    The steps What archives itself Publish the newsletter Add a Parish News issue Questions people ask
    The steps

    From a request to a live page

    1. Say what you'd like changed

    In plain English, in Claude Desktop's Code tab — "add this event to the calendar" or "the phone number on the Contact page is wrong". No file names or technical terms needed.

    2. Claude finds and edits the file

    You can ask to see the change before it goes any further, and ask for tweaks — nothing is final until you're happy with it.

    3. Claude checks its own work

    The site's automatic tests run, and Claude confirms the change is secure and stays readable for screen readers and other assistive technology — this site's standing rule is that nothing goes live untested.

    4. Claude saves it to GitHub

    This step is called a "push" — the moment your change leaves your laptop and joins the master copy. See Git & GitHub, in plain English if these words are new to you. Each push also gets its own version number, shown in the site's footer and beside every entry on /updates — behind the scenes, that same number tags an exact, permanent snapshot of the site at that point. In the extremely unlikely event you ever needed to step back to a known-good version, that's what would make it possible — just ask Claude.

    5. The live site rebuilds itself

    A process behind the scenes notices the new version on GitHub and publishes it automatically — usually in well under a minute. There's nothing for you to do at this step.

    6. Check it went live

    Visit /updates and look for your change at the top of the list, with today's date. If it's not there after a minute or two, just ask Claude to check.

    Automatic housekeeping

    What archives itself, and what doesn't

    A couple of areas of the site tidy themselves up on a schedule — worth knowing so you don't go looking for a manual step that doesn't exist, and so you know when a manual check really is needed.

    Noticeboard → Services & Events archive

    Any noticeboard card on the homepage with an expiry date moves itself to the Archive section of Services & Events the moment that date passes. No need to remove or move it by hand.

    InSpire Newsletter → Newsletter archive

    Each issue listed on the InSpire Newsletter page moves itself to the newsletter archive once it's more than six months old. Nothing to do here either.

    Parish News does not archive itself

    Unlike the two above, publishing a new Parish News issue means updating three separate places by hand — the homepage teaser, the Parish News page's latest issue, and the archive. See Add a Parish News issue below, and always check it once it's live.

    Common task

    Publish the InSpire Newsletter

    Three steps — the first two happen through Claude, the last one happens directly in MailerLite.

    1. Ask Claude to create it

    Tell Claude you're ready for the next issue and give it the items to include. Claude adds it to the website as a new InSpire Newsletter issue.

    2. Review, then ask for the one-page version

    Once the website has been updated, ask Claude for any corrections you'd like. When you're happy with it, ask Claude to create a one-page version of the newsletter — a self-contained file, styled to match, ready for MailerLite.

    3. Send it from MailerLite

    Upload that file into the correct group in MailerLite and send it out to subscribed users. This last step happens in MailerLite's own dashboard — not something Claude can do on your behalf.

    Common task

    Add a Parish News issue

    Because this one touches three places by hand (see What archives itself above), it's worth a quick check once it's live.

    1. Upload the PDF to Claude

    Drop the new issue's PDF into Claude Desktop's Code tab and ask Claude to update the site with it.

    2. Claude updates the site

    The usual six-step process — Claude updates the homepage teaser, the Parish News page's latest issue and the archive, then tests and pushes it live.

    3. Check it once it's live

    Visit the homepage and the Parish News archive and confirm the new issue's cover image and download link both look right in all three places.

    Questions people ask

    A few things worth knowing

    Can I break the website?

    It's very hard to. Claude runs the site's tests and its security and accessibility checks before anything goes live, and every change is recorded in Git's full history — so even a mistake can always be undone.

    Do I need to remember any commands?

    No. Everything happens through ordinary conversation with Claude — you never need to type a technical command yourself.

    What if I want to undo a change?

    Just ask Claude. Because Git keeps every past version, an earlier version of any page can always be brought back — see When it goes wrong for the full picture, including when it's quicker to just describe the fix instead.

    Where do I check my change went live?

    /updates lists every change to the site, newest first, each with the date and a short description of what changed.

    Who can see this help page?

    This page isn't linked from anywhere on the main site and won't turn up in search, but it isn't password-protected either — treat its address as something to share only with people who'll be helping update the site.
